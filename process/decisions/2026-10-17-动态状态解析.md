# B2 动态状态解析基线（2026-10-17）

负责人：B2 / Dynamic State
输入：B1 `RetrievalResult`
输出：`QueryResponse`

## 1. 边界

B2 不改变 B1 的检索排序，也不把 `score` 当作事实可信度或时间顺序。B2 负责：

1. 判断候选 Memory 之间的动态关系；
2. 选择回答本次问题所需的 Effective Memory；
3. 只根据 Effective Memory 生成答案与证据引用；
4. 冲突无法消解或证据不足时返回 `answer: null`。

实现通过 `DynamicStateResolver` 协议与 HTTP 层解耦。当前采用规则优先、LLM 可选的混合实现，
不改变 `QueryResponse`。

## 2. 关系规则

状态槽位使用 `subject + attribute` 标识：

| 情况 | 关系 |
|---|---|
| 同一槽位、相同值 | `RETAIN` |
| 同一槽位、值不同且时间有先后 | `SUPERSEDE` |
| 同一槽位、值不同且无法确定先后 | `CONFLICT` |
| 同一主题命名空间下的不同属性按时间补充 | `UPDATE` |

主题命名空间取 `attribute` 第一个 `.` 之前的部分。例如
`dance_studio.lifecycle_stage` 与 `dance_studio.business_health` 属于同一主题，但不是同一状态槽位。

只输出可比较 Memory 之间的关系，不为每个无关候选制造 `RETAIN` 边。

### LLM 裁决边界

- 同槽位且规范化后的值完全相同：规则直接判断为 `RETAIN`。
- 同槽位值不同，且两边都有明确、不同的事件/生效日期：规则直接判断为 `SUPERSEDE`。
- 只有对话时间或 Session 顺序不能证明状态发生顺序；此时与无序冲突、同主题不同属性一起交给
  LLM 判断，以识别近义值、历史回忆、继续确认、纠正、取消等语义。
- LLM 只能输出四种既有关系和简短理由，使用严格 JSON Schema 校验。
- API 异常、拒答、输出不完整或校验失败：自动回退到规则；默认 `rules` 模式不联网。
- LLM 输入不含检索得分的判断语义；提示明确禁止用 rank/score 判断事实真假或新旧。

配置：`DMS_STATE_RESOLVER=hybrid`、`DMS_LLM_PROVIDER=openai|deepseek`、
`DMS_LLM_MODEL=<model>`，以及对应的 `OPENAI_API_KEY` 或 `DEEPSEEK_API_KEY`。DeepSeek
使用官方 OpenAI 兼容端点和 JSON Output 模式，默认模型为 `deepseek-flash`。

## 3. 时间降级顺序

动态判断优先使用事件或状态生效时间。共享 Memory Schema 目前只有 Session 时间，因此基线按以下顺序降级：

1. 当契约后续加入 `time.effective_at` 时优先使用；
2. 当前先解析 `content` 中明确写出的绝对日期；
3. 使用 `time.date_time`（来源 Session 时间）；
4. 使用 `session_id` 的数字顺序；
5. 仍无法排序的不同值判为 `CONFLICT`。

`time.date_time` 不能假定为事件发生时间。例如 6 月 19 日对话中的“明天开业”，实际生效时间是 6 月 20 日。

## 4. Effective Memory 与答案

- `SUPERSEDE` 链中的旧值不作为普通“当前状态”回答。
- 持续时间问题允许两个 Effective Memory，并用 `start_time` 与 `end_time`（或 `opening_time`）标明角色。
- 答案证据只引用 Effective Memory 的 `evidence`，不引用被检索到但未参与答案的 Memory。
- `degraded=true`、空候选或未解决冲突不生成答案。

LoCoMo 演示问题沿用数据集口径，以跨越的日历月份计数，得到 `six months`；不把该演示口径当作通用精确时长算法。

## 5. 已知限制

- 当前规则依赖 A 提供稳定的 `subject` 与 `attribute` 命名。
- 相对时间和复杂时间区间仍需要 A 的 `effective_at` 或后续时间解析器。
- 主题命名空间是原型约定，不能替代正式实体/状态本体。
- 通用自然语言答案目前使用保守模板；复杂问答后续可接入受结构化输出约束的 LLM。

## 6. 评测

`evaluation/cases/b2_relations.json` 包含 7 个基础用例：来自 LoCoMo `conv-30`、`conv-42`、
`conv-49` 的 6 个样例，以及 1 个手工构造的无序冲突样例。另有
`evaluation/cases/b2_relations_challenge.json` 的 9 个语义难例，覆盖纠正、相对时间、取消、
近义表达、历史回忆和持续确认。默认共评测 16 组，覆盖四种关系标签。

```bash
python -m evaluation.state_accuracy
python -m evaluation.state_accuracy --resolver hybrid --model <model>
```

报告包含逐例结果、总体准确率、分标签准确率、混淆矩阵和无预测数。当前数据量只适合作为
B2 回归基线，不能代表完整泛化能力；后续应继续增加隐含改写、相对时间和多跳状态链样例。
