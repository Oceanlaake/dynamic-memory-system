## 第 1 页：项目目标、需求与总体设计

- 标题、团队和成员用紧凑页首，不占整页。
- 摘要概述长期对话状态变化、系统目标、已实现能力与实验发现，避免“全面优于 Vector”等结论。
- 核心需求压为三点：结构化 Memory/JSON 与证据回链；检索与动态关系分析；回答及 Web 可视化。
- 用一张图展示：LoCoMo → Memory → 检索 → 可选补检 → 关系/时间规则 → 候选证据包 → LLM → 引用校验/Web。
- 在图中标出本地处理和答案模型调用，避免把全部模块都画成 LLM。

## 第 2 页：关键实现与中期后改进

按三个要点写，不展开所有函数和 API：

1. **Memory 与动态关系**：内容、主体/属性、生效/对话时间、来源 session/turn；RETAIN、UPDATE、SUPERSEDE、CONFLICT；保留历史，集合事实不机械互斥。
2. **Bonus 检索**：查询补检处理同槽位/邻近证据；Graph Memory 将人物、槽位、Session、Turn 与 Memory 显式建图，并从 Top-K 种子执行有界多跳遍历，返回可审计路径。
3. **答案与可追溯性**：全部有界候选及原文证据进入共享 LLM 链路，规则选中仅为提示；实际引用与规则建议分开，失败无模板兜底。

限定 Graph Bonus 为有界结构化多跳检索，不宣称开放式多跳 Agent、自动因果推断或 Memory 压缩。

0.2000→0.1882、平均输入 Token 669.1→1030.6；必须说明小幅 F1 收益、上下文干扰与预算上限。

## 第 3 页：功能验证与实验方法

- 用当前 Web 小截图证明可以查看 Memory、关系、答案与来源，附一句功能/接口验证结论；模拟测试不能冒充真实模型成绩。
- LoCoMo 自定开发 conv-41/42/43/44、测试 conv-47/48；当前 340 题测试已暴露，50 题只是其中的先导子集。
- 五组：Full Text、纯 Embedding K5、Hybrid K5+rules、K5+补检+rules、Hybrid K10+rules。
- 两模型完成：DeepSeek Flash、GLM-4-Flash-250414；GLM-4.7 因 429/1305 阻塞，无有效成绩。
- 固定 Memory、rules、单轮、输出上限 1024，Hybrid 权重 BM25 0.4 / embedding 0.6；答案均为真实 LLM 生成。
- 指标为本地 F1、EM、证据召回、候选数、API 输入/输出 Token、错误/拒答。F1 不等于语义准确率；失败计 0，不能删题。
- 说明同模型同轮相同输入复用，方法等价用量与实际请求支出分开；只统计答案模型，不包含抽取/embedding/Judge。
- 完整配置与源码/数据哈希用仓库链接引用，不在正文展开日志、命令和完整需求追踪表。

必须写出的判断：

- DeepSeek 全文 F1=0.5043、Vector=0.4069、基础系统=0.3976、补检系统=0.4075；整体没有稳定优于 Vector。
- 旧 GLM 全文 300/340 协议错误，应醒目标为协议不稳定，不用于证明语义优势；不能只留下其 0.0405 分数而省略失败背景。
- 方法对比体现回答质量与输入消耗的折中，不能把节省输入 Token 直接等同于更便宜的全部系统。

## 第 5 页：补检消融、局限与结论

用两个模型各三组的 6 行表，列 K5/K10/补检的 F1、Memory 召回、平均候选、平均输入 Token。
概括：召回约 59.9%→65.0%，候选 5→6.81；K10 约 67.5% 和 9.99 条。
DeepSeek 补检 F1 约 +0.0099，旧 GLM 约 −0.0015；相比 K10 输入 Token 约少 23%，并非无损或统计等效。

用简短一段解释：找回证据不保证正确利用；可能存在额外上下文干扰、引用/格式错误和词面评分局限。
如版面允许，用一句正/反案例作佐证；详细案例留给 PPT/仓库，不强塞两张大截图。

局限至少保留：已暴露的两段测试对话、单轮、动态专项样本少、缺官方关系金标、GLM 协议失败。
不把小型关系回归包装成端到端动态状态准确率，不把“记忆多导致混淆”写成唯一已证实原因。
结论回到完成的工程能力、召回收益和模型相关的答案效果；页末放少量必要参考文献与仓库/结果入口。
