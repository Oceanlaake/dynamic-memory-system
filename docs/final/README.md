# 最终材料与写作分工

本目录是最终报告和展示材料的入口。先读 [340 题正式结果](../large-scale-results-2026-11-05.md)；数字、失败率和限制以该文及 [轻量结果包](../../evaluation/results/submission-v1/README.md) 为准。

## 要完成什么

最终只提交一份综合报告，**整份不超过 5 页**；PPT **整份不超过 10 页**。封面、参考文献和任何附录均计入对应页数，不另交第二份测试报告。

| 材料 | 负责角色 | 本轮提供的起点 | 交付建议 |
|---|---|---|---|
| 内部测试记录整理 | 用户 | 正式结果、逐题 CSV、manifest、正反案例 | 仅作组内写作依据，不另行提交报告 |
| 唯一最终报告 | 1 位同学 | [5 页报告大纲](report-outline.md) | 需求、设计、实现与测试合并；源文件 + 总计≤5页的PDF |
| 最终 PPT | 2 位同学协作 | [10 页逐页大纲](presentation-outline.md) | 可编辑PPT + PDF，两者均≤10页 |
| 仓库与交付检查 | 用户统筹 | [提交结果包](../../evaluation/results/submission-v1/README.md) | 代码可运行、提交内容可复现、文档与数字一致 |

用户已说明没有末期现场展示；PPT 按提交型材料编写，每页有完整结论，不依赖口头讲解或现场 API 成功。
报告同学按五页安排整合；PPT同学A负责1–5页，B负责6–10页，合稿后统一术语、图表和排版。不额外安排封面/致谢/附录页。

## 共同口径

- 当前是自定 4 开发/2 测试，340 道已暴露 QA、单轮、两个可用模型；4.7 因限流没有有效成绩。
- F1 不是“正确率百分比”；EM 是严格匹配的辅助指标。主表同时列生成错误和拒答。
- DeepSeek 全文 0.5043、Vector 0.4069、基础系统 0.3976、补检 0.4075、K10 0.4243。
- 补检召回约 59.9% → 65.0%，相比 K10 输入 Token 少约 23%；答案 F1 收益依赖模型，不能写普遍提升。
- 旧 GLM Full Text 300/340 协议错误，不能作为正常语义能力基线；图表需要明确标注。
- 候选记忆不等于规则建议记忆，不等于 LLM 实际引用。有效 ID 校验不证明语义正确。
- 补检和 rules 无额外生成 LLM 调用，但更多上下文会增加答案输入 Token；没有全面成本免费结论。
- 本轮没有完整端到端动态状态准确率金标；小型关系回归不包装成真实 QA 独立准确率。
- Graph Bonus 使证据召回 59.92%→64.93%；同一 DeepSeek 成对对照中 F1 0.3896→0.3953，但 EM 0.2000→0.1824、输入 Token 增加 54.7%。必须作为收益/干扰/成本折中一起报告。

## 交稿前共同核对

唯一报告、PPT 和内部测试记录使用同一版本的表；全部数字可定位到结果包。
截图需来自当前网页，显示真实答案/引用/生成状态；旧模板或模拟 Demo 截图不能冒充本轮真实生成。
若暂时没有合适截图，先明确标为待补，不贴占位图后当最终证据。
最终检查数据划分、模型 ID、1024 输出预算、规则与候选含义、Token 范围、失败率和实验局限是否一致。
实际导出后确认报告总页数≤5、PPT/PDF总页数≤10，不依靠缩小到不可读字号或额外附录绕过限制。
