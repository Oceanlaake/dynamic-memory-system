# 查询驱动证据补检（v3）

本页说明当前实现；正式数字见 [340 题结果](large-scale-results-2026-11-05.md)。旧模板诊断和开发过程已本地归档，不作为报告主成绩。

固定 Top-K 可能遗漏状态历史或事实支持。旧版只允许动态问题补检，导致多数事实题被 `not_dynamic` 跳过。
v3 依据相关种子与证据关联补检，保留初始候选和顺序，不读取 QA 标准答案或参考 evidence。

| 策略 | 场景 | 查找方式 | 预算语义 |
|---|---|---|---|
| `state_history` | 显式动态标量状态 | 同主体、同属性历史闭包 | 历史被截断时保守跳过作答 |
| `query_evidence` | 普通事实、集合型或无属性记录 | 同槽位、同 turn、相邻 1 个 turn 的相关记录 | 新增至多 min(初始候选数, 配置上限)，预算不足不自动等同证据不充分 |

事实邻域须匹配问题主题和主体范围，按本地 BM25 及来源关联权重排序。
空属性不合并为共享槽位，集合事实的不同值不自动构成替代/冲突；明确对立值仍判断。
追加 score=0 是占位，不是重新计算的相关度；来源与新增原因独立展示。
实现位于 `backend/retrieval/evidence.py`、`backend/retrieval/expansion.py`。
接口保留 `expand_slots`、`max_expansion_memories`，输出策略与预算 trace。
只扫描同一对话样本，补检本身不调用 LLM。

补检后，规则提供关系和选用提示，全部有界候选及引文经 `backend/qa.py` 交给答案模型。
不只保留一条记忆，不按模板拼答案。新证据不保证被正确利用，也可能增加干扰和引用错误。

340 题上，Memory 召回约 59.9% → 65.0%，平均候选 5 → 6.81；K10 召回约 67.5%。
DeepSeek 补检 F1 约 +0.0099，旧 GLM Flash 约 −0.0015，未形成跨模型稳定提升。
相比 K10 平均输入 Token 少约 23%，属于本轮质量/消耗折中，不是全面胜出或统计等效证明。

此实现可对应 Bonus 的“自适应检索”方向，最终认定由课程评审决定。
该机制本身不是 Graph Memory；仓库现已另行实现有界 Graph Memory 多跳检索，见
[Graph Memory Bonus](graph-memory.md)。仍未实现开放式多跳 Agent、Memory 压缩或自动因果推断。
种子缺失、远距离证据、抽取错误、属性别名及答案模型能力仍限制效果。
