### Full Text 的协议稳定性（重要）

`glm-4-flash-250414` 的 Full Text 有 300/340 个协议错误：120 个 JSON 解析失败、
91 个截断（finish_reason=length）、89 个无效引用；即使输出预算放大到 1024 仍如此。
因此它的 Full Text F1=0.0405 不能作为正常作答基线，也不能用来证明系统在语义理解上
大幅领先。`deepseek-flash` 的 Full Text 0 个协议错误，F1=0.5043，可作为有效基线。

## 结论口径

1. 两个可用模型上，补检使 Memory 集合召回从 0.599 提升到 0.650（+5.1 个百分点），
   K=10 为 0.675。但召回提升没有稳定转化为答案 F1：DeepSeek 补检 +0.0099、
   GLM 补检 −0.0015；K=10 在 DeepSeek 上比 K=5 高 0.0267，在 GLM 上反而低 0.0171。
2. “系统整体高于纯 Vector”在两个模型上均未被 K=5 证实：DeepSeek 的 K5+rules
   0.3976 略低于纯 Embedding 0.4069；GLM 基本持平。只有 DeepSeek 的 K=10
   （0.4243）本轮数值高于纯 Vector，未做显著性证明。整体收益与补检净收益是两件事，不互相替代。
3. Full Text 结论仅对 DeepSeek 成立（0.5043，0 协议错误）；GLM-4-flash 的 Full Text
   因协议失败（300/340）不计入语义对照。
4. DeepSeek 在所有检索方法上均高于 GLM-4-flash-250414；跨模型 Token 不等于费用，
   不能按共同单价比较。
5. 本结果是自定已暴露测试集、单轮、两个可用模型；GLM-4.7-flash 因 429/1305 阻塞，
   不构成完整三模型结论，后续限流缓解可单独补测。
